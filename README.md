# 국가 건설 & 전쟁 게임 (서버 권위 프로토타입)

격자 필드 위에 국가를 세우고, 자원을 채굴·가공하고, 다른 유저의 국가와 싸우는
브라우저 게임입니다. 프런트엔드는 순수 HTML/JS라 GitHub Pages에 바로 올릴 수
있고, 자원 계산 등 핵심 로직은 전부 **Firebase Cloud Functions(서버 권위)**
에서 처리합니다. **키보드 없는 태블릿/폰 사용을 기본으로 설계**했고
(터치 팬·핀치줌·탭, 화면 버튼), 전쟁은 **클래시 오브 클랜식 비동기 대전**
(트로피·보호막·매치메이킹) 방식이며, 실제 전투는 상대 기지 스냅샷 위에서
유닛을 실시간으로 소환해 싸우는 **실시간 습격 전투**로 진행됩니다.

- **4단계 가공 체인**: 목재→판자, 석재→벽돌 같은 1단계 가공부터, 주괴 제련
  (2단계), 회로기판·철근 같은 고급 부품(3단계), 총기·방탄조끼 등 군사 장비
  (4단계)까지 공장/제련소/정제소 레시피로 전부 구현했습니다(`data.js`의
  `STRUCTURES.factory.recipes`, `STRUCTURES.smelter.recipes` 등).
- **병력 모집 시스템**: 전초기지에서 국고 골드로 병종을 모집(대기열 등록) →
  컨베이어 벨트로 필요 장비를 투입하면 자동으로 무장 완료되어 로스터에
  편입됩니다. 공격 유닛 10종·수비 유닛 4종을 문서 스펙 그대로 반영했습니다.
- **터렛 6종 개별 구현**: TR-01~TR-06을 각각 별도 구조물로 분리했고, 건설
  비용(골드+아이템)뿐 아니라 **지속 전력 소모(kW)** 도 반영됩니다 — 발전소
  공급 범위 안에 있어도 전력이 부족하면 그 턴은 작동을 멈춥니다.
- **레벨업 비용 밸런스 조정**: 기존에는 채굴/가공/방어 등 같은 카테고리
  구조물끼리 레벨업 비용표(`LEVEL_COSTS`)를 공유해서, TR-01과 TR-06처럼
  성능 차이가 큰 구조물도 레벨업 비용이 완전히 같은 문제가 있었습니다.
  이제는 모든 구조물이 자신의 건설 비용(`baseCost`)을 기준으로
  `baseCost × upgradeCostMul^레벨`을 적용해 개별적으로 레벨업 비용이
  산정됩니다(`data.js`의 `getUpgradeCost`) — 같은 카테고리라도 티어가
  높은 구조물(공장 vs 제련소, TR-06 vs TR-01)일수록 레벨업 비용도
  비례해서 비싸집니다. (수도만은 예외로, 위에 적은 단계별 비용표
  `levelCosts`를 따로 씁니다 — 건설 자체는 여전히 무료)
- **실시간 습격 전투(전초기지 → 집결지 → 실시간 소환 전투)**: 기존의 "공격력
  vs 방어력 숫자 비교 즉시 판정"을 폐기하고, 클래시 오브 클랜식 실시간 습격
  전투로 완전히 교체했습니다(`js/battle.js` + `js/battleRender.js`).
  - **집결지(공격 덱)**: 전초기지에서 모집·무장 완료된 공격 유닛은 로스터에
    쌓여있다가, "공격" 버튼을 누르면 그대로 이번 습격의 "덱"이 됩니다(별도로
    출정 유닛을 미리 고르는 화면은 없고, 전투 화면에서 실시간으로 원하는
    만큼만 꺼내 씁니다).
  - **소환 및 AI**: 전투 화면은 상대 기지의 스냅샷을 보여주고, 공격자는
    상대 **영토 밖(소환 가능 영역)** 어디든 탭해서 유닛을 실시간으로
    소환합니다. 유닛마다 고유 타깃팅 우선순위가 있습니다 — 기초 돌격병
    등은 가장 가까운 아무 구조물을, 중갑 공성병·공성 투석/전차는 터렛·
    방벽만, 마도 폭파 특공대는 가장 가까운 방벽으로 돌진해 큰 피해를 주고
    자폭, 공중 침투 드론은 장애물을 무시하고 발전소(없으면 수도)를 직행
    타격합니다.
  - **수비 유닛 자동 반응**: 방어 진형병은 가장 가까운 공격 유닛에게 이동해
    어그로를 끌고, 저격 수비병은 제자리에서 사거리 내 적을 저격하며, 수리
    공병은 손상된 터렛/방벽으로 이동해 실시간으로 회복시키고, 마도 결계병은
    느리지만 강한 근접 수비병으로 움직입니다.
  - **전력망 파괴 전략**: 발전소(또는 수도의 영토 전력 공급 범위)가 파괴되면
    그 범위 안 터렛은 실시간으로 즉시 먹통이 됩니다.
  - **승리 조건**: 제한 시간(150초) 안에 **파괴율 50% 이상**을 달성하면
    승리, 수도까지 파괴하면 파괴율과 무관하게 **완벽한 승리**(최대 약탈)
    입니다. 약탈량은 달성한 파괴율에 비례해 방어자의 현재 자원에서 계산됩니다.
  - **비영구적 파괴**: 방어자의 구조물은 전투에서 얼마나 부서지든 다음
    전투 때 항상 원래 체력으로 다시 시작합니다(클래시 오브 클랜 방식) —
    오직 **자원만 영구적으로 약탈**됩니다. 배치했던 공격 유닛은 생존 여부와
    무관하게 이번 습격에서 전부 소모됩니다(다시 모집해야 함).
  - **아키텍처**: 이 프로토타입엔 실시간 소켓 서버가 없으므로, 전투 전체는
    **공격자 브라우저에서 방어자의 Firestore 스냅샷을 가지고 로컬로
    시뮬레이션**됩니다(클래시 오브 클랜이 오프라인 상대의 스냅샷과 싸우는
    것과 같은 구조). 서버(`submitRaidResult`)는 전투를 재생하지 않고 최종
    결과(파괴율·약탈량)만 받아 **방어자가 현재 보유한 자원 한도로 다시
    클램프**하고 `win`도 `destructionPercent`로부터 다시 계산해서 신뢰
    경계를 지킵니다 — 클라이언트가 조작한 `win:true`나 부풀린 약탈량은
    반영되지 않습니다.

### 문서에 없어서 임의로 정한 부분 (설계 가정)

원본 문서에 수치·출처가 없던 항목은 아래처럼 임의로 정했습니다. 밸런스가
안 맞으면 해당 상수만 고치면 됩니다.
- **국고 골드(Gold)의 생산 출처**: 문서에 명시되어 있지 않아, 수도가 레벨에
  비례해 매 틱 골드를 생산하도록 임의로 추가했습니다(`STRUCTURES.capital.goldIncome`).
- **유닛별 전투력(`power`) 수치**: 문서는 모집 비용/장비만 정의하고 전투력
  수치는 없어서, 모집 비용에 비례해 임의로 산정했습니다(`data.js`의 `UNITS`).
- **회로기판의 "금 주괴 1개 추가(선택)" 옵션**: 기본 레시피(구리선+플라스틱)만
  구현했고, 금 주괴를 추가하는 상위 변형 레시피는 아직 없습니다.
- **구조물 최대 체력**: 실시간 전투에서만 쓰이는 값이라 문서에 없어서,
  구조물 부피/티어에 비례해 임의로 산정했습니다(`data.js`의 `baseHp`,
  `getStructureMaxHp` — 레벨 1당 25%씩 증가).
- **유닛별 체력/이동속도/사거리/공격주기**: 마찬가지로 문서에 없어 모집
  비용·전투력에 비례해 임의로 산정했습니다(`data.js`의 `UNITS.*.hp/speed/range`).
- **수비 유닛의 전투 중 배치 위치**: 로스터에 수량만 저장되고 좌표가 없어서,
  전투 시작 시 터렛/방벽(없으면 수도) 주변에 자동으로 흩어 배치되는 것으로
  가정했습니다(`battle.js`의 `createBattleSession`) — 별도의 "수비 배치
  편집" 화면은 아직 없습니다.
- **소환 가능 영역(Drop Zone)**: 문서는 "방어선이 미치지 않는 영역"이라고만
  설명해서, 구현은 이를 **방어자의 영토 밖 전체**로 단순화했습니다(터렛
  사거리를 개별 계산해 영역을 깎아내는 정교한 판정은 아직 없습니다).
- **약탈량 산정 방식**: "구조물을 파괴할 때마다 즉시 약탈"이라는 설명을,
  개별 창고 자원 매핑이 없는 현재 자원 모델에 맞춰 **최종 파괴율에 비례한
  일괄 약탈**로 단순화했습니다(`BATTLE.lootRatePerHp`, 완벽한 승리 시
  `perfectVictoryLootMul` 배율 적용).
- **전투 제한 시간**: 문서에 구체적인 시간이 없어 150초로 임의로 정했습니다
  (`data.js`의 `BATTLE.durationSec`).
- **인벤토리/창고 용량과 수동 이송량**: 문서에 수치가 없어 임의로 정했습니다
  (`data.js`의 `LOGISTICS` — 산출 인벤토리 50+레벨당 25, 창고 500/레벨,
  수도 보관 200/레벨, 수동 이송 1회 10, 수동 운용 배율 50%·간격 600ms).
- **골드·전력은 창고에 보관하지 않습니다**: 실물 아이템이 아니라서 창고를
  거치지 않고 수치로만 관리합니다(`data.js`의 `VIRTUAL_RESOURCES`).

## 1. 로컬에서 바로 확인 (오프라인 모드)

빌드 도구 없이 정적 서버만 있으면 됩니다.

```bash
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 접속
```

Firebase 설정 전에는 **로컬(오프라인) 모드**로 동작합니다. 이때는 브라우저
자신이 곧 "서버" 역할을 해서 `js/logic.js`·`js/simulate.js`를 직접 실행하므로,
건설·자원 생산·레벨업·연구까지 네트워크 없이 전부 테스트할 수 있습니다.
상단 HUD에 `로컬 모드`로 표시됩니다. (건국하기 버튼을 누르면 즉시
플레이가 시작되고, Firebase가 연결되면 그 다음에 온라인 모드로 전환됩니다.)

## 2. Firebase 프로젝트 준비

1. https://console.firebase.google.com 에서 새 프로젝트 생성
2. **Firestore Database** 생성 (프로덕션 모드로 시작해도 됨 — 아래 `firestore.rules`가
   클라이언트 직접 쓰기를 전부 막아주므로 테스트 모드일 필요가 없습니다)
3. **Authentication → Sign-in method → 익명 로그인(Anonymous)** 활성화
   (회원가입 없이 플레이어를 구분하기 위한 용도)
4. 프로젝트 설정 → "웹 앱 추가" → 나오는 설정 객체를
   `js/firebase-config.js`의 `FIREBASE_CONFIG`에 붙여넣기
5. **Blaze(종량제) 요금제로 업그레이드** — Cloud Functions와 예약 함수
   (Cloud Scheduler)를 쓰려면 필요합니다. 무료 티어 한도 안에서는 과금되지 않습니다.

## 3. Cloud Functions 배포 (서버 권위 로직)

```bash
npm install -g firebase-tools   # 최초 1회
firebase login
firebase init                    # 이미 있는 firebase.json/firestore.rules를 그대로 사용해도 됨
cd functions && npm install && cd ..
firebase deploy --only functions,firestore:rules
```

배포가 끝나면 `submitInitNation / submitBuild / submitUpgrade / submitSetRecipe /
submitStartResearch / submitRecruitUnit / submitRaidResult` callable 함수와, 1분마다 모든 국가의
자원 생산·벨트 물류·전력·연구를 계산하는 예약 함수 `productionTick`이
활성화됩니다. 배포 후 사이트에 접속하면 상단 HUD가
`온라인 (서버 권위 모드)`로 바뀌고, 이후 모든 건설/전투 요청은 클라이언트가
직접 계산하지 않고 Cloud Functions에 "요청"만 보냅니다.

> Cloud Functions를 배포하지 않아도 게임 자체는 오프라인 모드로 완전히
> 플레이 가능합니다. 멀티플레이어(다른 유저와의 전쟁)만 서버가 필요합니다.

## 4. GitHub Pages 배포 (프런트엔드)

1. 이 폴더 전체(특히 `index.html`, `css/`, `js/`)를 GitHub 저장소에 push
   (`functions/`는 GitHub Pages에 올릴 필요 없이 Firebase에만 배포하면 됩니다)
2. 저장소 Settings → Pages → Source를 `main` 브랜치 `/ (root)`로 설정
3. 몇 분 후 `https://<계정>.github.io/<저장소명>/` 에서 접속 가능

`type="module"` 스크립트를 쓰므로 **반드시 http(s) 서버**로 열어야 합니다
(파일을 더블클릭해서 `file://`로 열면 동작하지 않습니다).

## 게임 규칙 요약

- 격자 필드는 **고정 시드**(`world.js`의 `WORLD_SEED`)로 생성되어, 별도 저장 없이
  모든 클라이언트/서버가 동일한 지형(숲/채석장/석탄·철·금·구리광산/원유 분출구/
  마석광산/강·호수)을 계산해냅니다.
- 국가는 **수도**(부피 9)로 시작하며 주변 타일이 자동으로 영토가 되고, **수도를
  레벨업할수록 편입되는 영토 반경도 함께 넓어집니다**. 단, 수도는 **초기 영토
  안에 나무 숲과 채석장이 각각 최소 1개씩 들어오는 자리에만** 세울 수 있습니다.
- **중심지**는 반드시 기존 영토 안에만 지을 수 있으며, 지어진 중심지를
  기준으로 그 주변이 추가로 영토에 편입됩니다. 중심지도 레벨업할수록
  편입 반경이 넓어집니다.
- 광산/유전/추출기는 해당 자원 노드 위에만, **농지는 물 옆에만** 지을 수 있습니다.
- 구조물은 건설 후 자원을 추가로 소모해 **레벨업**(최대 Lv.5)할 수 있습니다.
- **연구소**를 지으면 좌측 패널에서 클릭 → 해금 가능한 구조물의 기술 트리가
  나타납니다. 선행 연구·자원·소요 틱을 만족해야 연구를 시작할 수 있고,
  연구소가 없거나 이미 해금된 항목은 연구할 수 없습니다.
- **컨베이어 벨트**는 건설 시 R키로 방향을 회전할 수 있습니다(→↓←↑). 구조물이
  산출한 자원은 인접한 벨트가 있으면 벨트를 타고 다음 구조물로 흘러가고,
  없으면 그 구조물의 **산출 인벤토리에 그대로 쌓이고, 가득 차면 가동이
  멈춥니다**. 쌓인 자원은 벨트나 수동 이송으로 **창고(수도 포함)** 까지 옮겨야
  국고에 잡히고 건설·연구·모집에 쓸 수 있습니다. 가공 구조물의 재료와 발전소
  연료도 반드시 벨트나 수동 이송으로 해당 구조물에 넣어줘야 합니다.
- **창고**는 한 곳에 **한 종류의 자원만** 보관합니다(첫 자원이 종류를 정하고,
  비우면 다시 아무 자원이나 받습니다). 전력이 없는 구조물은 패널의
  **"✋ 수동 운용" 버튼을 누르고 있는 동안** 손으로 돌릴 수 있습니다.
- **수도의 영토 범위**(레벨에 비례해 넓어짐) 안에서는 발전소 없이도 항상
  전력이 공급됩니다. 그 범위를 벗어난 영토(중심지로 확장한 먼 땅)에서는
  **발전소**가 주변 일정 범위(레벨에 비례)에 전력을 공급해야 합니다.
  채굴/생산/터렛 카테고리 구조물은 전력 범위 밖이면 "정지(idle)" 상태가
  되어 가동을 멈춥니다. 필드에서 **P키**를 누르면 전력 공급 범위를
  반투명 원으로 확인할 수 있습니다.
- 전투(습격/침입)는 오직 **플레이어 간 전쟁**으로만 발생하며, 매치메이킹으로
  상대를 찾은 뒤 "공격"을 누르면 **실시간 습격 전투 화면**이 열립니다.
  전초기지에서 모집·무장한 공격 유닛을 상대 영토 밖에 실시간으로 소환하면
  유닛마다 정해진 AI로 스스로 이동·타격하고, 수비 유닛과 터렛(전력이
  살아있는 것만)이 자동으로 맞섭니다. 제한 시간 안에 **파괴율 50% 이상**을
  달성하면 승리, 수도까지 파괴하면 파괴율과 무관하게 완벽한 승리이며,
  약탈량은 최종 파괴율에 비례해 방어자의 자원에서 계산됩니다. 방어자의
  구조물 자체는 영구 파괴되지 않고, 오직 자원만 영구적으로 약탈됩니다.
- 다른 국가 목록은 내 수도 기준 **주변 지역(3×3 버킷)** 안의 국가만 조회합니다
  (전체 국가를 다 구독하지 않도록 지역 기반 쿼리로 축소).

## 알려진 단순화 (다음 단계로 고려할 것들)

- **연구는 국가당 동시에 1개만** 진행됩니다(연구소를 여러 채 지어도 병렬
  연구는 안 됨) — 단순화된 규칙입니다.
- **벨트가 도중에 끊기면** 그 지점에서 남은 자원은 창고로 반환됩니다(유실
  방지를 위한 안전장치). 실제 컨베이어 게임처럼 "막히면 자원이 벨트 위에
  쌓이는" 정교한 흐름 시뮬레이션은 아닙니다.
- **지역 버킷은 진짜 geohash가 아니라 100칸 단위 격자 버킷**입니다. 목적(쿼리
  범위 축소)은 동일하게 달성하지만, 극지방 왜곡 등을 고려하는 실제 geohash
  라이브러리(`ngeohash` 등)로 교체할 수 있습니다.
- `functions/shared/*.js`는 `js/*.js`의 **수동 복사본**입니다. 빌드 도구가
  없는 프로토타입이라 그렇게 했고, 실서비스로 키운다면 두 곳에서 같이 쓰는
  공용 npm 패키지(workspace)로 분리하는 걸 권장합니다.
